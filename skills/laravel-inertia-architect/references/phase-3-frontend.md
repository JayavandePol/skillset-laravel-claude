# Phase 3 — Frontend: React + Inertia v3 + Tailwind v4

Verify against the Inertia v3 docs before writing code; v3 changed setup (Vite plugin, built-in HTTP client) compared to v1/v2 tutorials still common online.

## Directory structure

Start from the React starter kit layout and extend it:

```
resources/js/
├── app.tsx                 # createInertiaApp
├── ssr.tsx                 # SSR entry
├── pages/                  # one file per Inertia page; mirrors controller names
│   ├── dashboard.tsx
│   ├── boards/
│   │   ├── index.tsx
│   │   └── show.tsx
│   └── settings/…
├── layouts/                # app-layout, auth-layout, settings-layout, board-layout
├── components/
│   ├── ui/                 # shadcn/ui primitives (generated — don't hand-edit heavily)
│   └── app-sidebar.tsx …   # app-wide composed components
├── features/               # domain components grouped by epic
│   └── kanban/
│       ├── board-canvas.tsx
│       ├── list-column.tsx
│       ├── card-tile.tsx
│       ├── card-dialog.tsx
│       └── use-card-move.ts
├── hooks/                  # generic hooks (use-appearance, use-mobile, use-debounce)
├── lib/                    # utils, zod schemas, formatters
├── types/                  # index.d.ts: SharedData, User, Workspace, generated DTO types
├── routes/ actions/ wayfinder/   # generated by Wayfinder — commit or gitignore per kit default
└── i18n/                   # translations if multi-language
```

**Why `features/`:** pages stay thin (layout + data → feature components); feature folders keep the kanban code together instead of scattering it over `components/`.

## Typed data contract PHP → TS

- Use **Wayfinder** for routes/controller actions in TS: `import { show } from '@/actions/App/Http/Controllers/BoardController'` → `show({ workspace, board }).url`. No string URLs in React.
- Generate prop types from PHP DTOs with `spatie/laravel-data` + `spatie/laravel-typescript-transformer`, or hand-write them in `types/` if the project is small. Either way every page gets a typed props interface.

```tsx
// pages/boards/show.tsx
import AppLayout from '@/layouts/app-layout';
import { BoardCanvas } from '@/features/kanban/board-canvas';
import type { BoardData, ListData, MemberData } from '@/types/generated';

interface Props {
  board: BoardData;
  lists: ListData[];
  members?: MemberData[]; // optional/deferred prop
}

export default function BoardShow({ board, lists, members }: Props) {
  return (
    <AppLayout breadcrumbs={[{ title: board.name, href: '#' }]}>
      <BoardCanvas board={board} lists={lists} members={members} />
    </AppLayout>
  );
}
```

## State management

Inertia removes most global client state. Use this hierarchy, from first choice to last:

1. **Server props** — the source of truth. After a mutation, redirect back; Inertia merges the new props.
2. **Shared data** (`HandleInertiaRequests::share`) — auth user, current workspace, permissions for the UI, flash, feature flags, locale. Keep it small; it ships on every response. Use lazy closures for anything costly.
3. **URL state** — filters, sort, tabs, open card ID (`?card=01J…`) via `router.get(url, params, { preserveState: true, replace: true })`. Shareable and survives refresh.
4. **Local component state / `useRemember`** — form drafts, UI toggles (`useRemember` restores on back-navigation).
5. **Layout props (v3)** — share data between a page and its persistent layout without context hacks.
6. **React context / Zustand** — only for genuinely client-only cross-tree state (e.g. drag & drop session, command palette). Avoid duplicating server data in a store.

```php
// app/Http/Middleware/HandleInertiaRequests.php
public function share(Request $request): array
{
    $workspace = app(CurrentWorkspace::class)->get();

    return [
        ...parent::share($request),
        'auth' => [
            'user' => $request->user()?->only('id', 'name', 'email', 'avatar_url'),
        ],
        'workspace' => $workspace?->only('ulid', 'name', 'slug'),
        'can' => fn () => $workspace ? [
            'manageMembers' => $request->user()->can('manageMembers', $workspace),
            'createBoards' => $request->user()->can('create', [Board::class, $workspace]),
        ] : [],
        'flash' => fn () => $request->session()->only(['success', 'error']),
    ];
}
```

UI permission flags are for hiding buttons only; the server re-checks every request.

## Partial reloads, deferred & merged props

```php
return Inertia::render('boards/show', [
    'board'   => BoardData::from($board),
    'lists'   => fn () => ListData::collect($board->lists()->with(...)->get()), // evaluated only when requested
    'members' => Inertia::defer(fn () => MemberData::collect($workspace->members)), // loads after first paint
    'activity'=> Inertia::optional(fn () => $board->activities()->latest()->limit(50)->get()), // only on explicit partial reload
    'comments'=> Inertia::merge(fn () => $card->comments()->cursorPaginate(20)), // append on load-more / infinite scroll
]);
```

```tsx
router.reload({ only: ['lists'] });                 // refresh just the kanban after a realtime event
<Deferred data="members" fallback={<MembersSkeleton />}>…</Deferred>
<WhenVisible data="activity" fallback={<Spinner />}>…</WhenVisible>
<Link href={show(board).url} prefetch>Open</Link>   // prefetch on hover
```

Check the exact helper names (`Inertia::optional` vs older `lazy`, `Inertia::scroll` for infinite scroll) in the current docs.

## Optimistic UI (drag & drop)

Inertia v3 supports optimistic updates with automatic rollback across `router`, `useForm` and `useHttp`. Pattern for a card move:

1. `@dnd-kit` `onDragEnd` → compute new list + neighbour cards.
2. Update the local list order immediately (optimistic), then `router.post(move(card).url, payload, { preserveScroll: true, only: ['lists'] })` using v3's optimistic option (see the "Optimistic updates" docs page for the exact API).
3. On error, Inertia rolls back; show a toast.
4. Broadcast `CardMoved` to others via Reverb; their client does `router.reload({ only: ['lists'] })`.

Use `useHttp` for requests that shouldn't navigate or replace page props (autosave a description, typeahead search).

## Forms

- Default: Inertia `<Form>` component or `useForm` — handles CSRF, errors, `processing`, `progress` for uploads, `reset`, and dirty tracking.
- Complex client-side validation: React Hook Form + Zod, submitting through Inertia's router — see Phase 4 for the bridge.

## SSR

1. Ensure `resources/js/ssr.tsx` exists (starter kit provides it) and the Vite config enables SSR through `@inertiajs/vite` / `laravel-vite-plugin` (v3 auto-runs SSR in dev).
2. Build: `npm run build:ssr` (or `vite build && vite build --ssr` — check `package.json`).
3. Run in production as its own process/container: `php artisan inertia:start-ssr` (port 13714 by default); health check with `php artisan inertia:check-ssr`.
4. SSR-safe code: no `window`/`document`/`localStorage` at module top-level or during render; guard with `useEffect` or `typeof window !== 'undefined'`. Dnd-kit, charts and editors should render a placeholder on the server.
5. Use SSR for public/SEO pages (landing, public boards); app-only installs can disable it to save a container — decide in Phase 0.
6. Set `<title>` and meta via Inertia's `<Head>`; the root Blade view keeps `@inertiaHead`.

## Tailwind v4 & UI

- Tailwind v4 is CSS-first: theme tokens in `resources/css/app.css` with `@theme`, no `tailwind.config.js` by default.
- shadcn/ui components via `npx shadcn@latest add dialog dropdown-menu …`.
- Dark mode via the kit's appearance hook (class strategy).
- Accessibility: dialogs/menus from Radix/shadcn are keyboard-accessible; dnd-kit has keyboard sensors — enable them.
- Filament has its own Tailwind theme/build; don't share `app.css` with it (Phase 5).
